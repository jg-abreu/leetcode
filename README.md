My personal collection of LeetCode solutions, written while I study data structures and algorithms. Each problem includes the solution code and short notes on the reasoning behind it.

## 🎯 Goals

- Build a **consistent practice habit** — a little every day beats a lot once in a while.
- Learn to recognize **common patterns** (hashing, two pointers, sliding window, etc.) instead of memorizing answers.
- Always start with a **brute-force solution**, then look for a better one.
- Prepare for **technical interviews** and coding assessments.

## 🛠️ Languages

| Language | Why I use it |
|---|---|
| **Python** | Concise syntax — great for focusing on the logic of the algorithm. |
| **Java** | Strong typing and explicit structure — great for practicing the language used in many interviews. |

Some problems are solved in both languages, so the two versions can be compared side by side.

## 📁 Repository Structure

Solutions are pushed automatically by [LeetHub v2](https://github.com/arunbhardwaj/LeetHub-2.0) after each accepted submission. Each problem gets its own folder:

```
leetcode/
├── README.md
├── 0001-two-sum/
│   ├── README.md          ← problem statement
│   ├── 0001-two-sum.java  ← Java solution
│   ├── 0001-two-sum.py    ← Python solution (when available)
│   └── NOTES.md           ← my notes (approach, complexity, lessons)
└── ...
```

## 📝 Notes Template

For each problem, I write a short `NOTES.md` file:

```markdown
## Approach
Brief explanation of the idea in 2–3 lines.

## Complexity
- Time: O(?)
- Space: O(?)

## What I learned
Mistakes I made, new concepts, or patterns worth remembering.
```
